# Prepare and run schema-4 AHPC-NOCI

[中文](AHPC_NOCI_Preparation_and_Run.zh.md)

The complete input and scientific explanation is the [standard-case tutorial](../../examples/ahpc_noci_standard/TUTORIAL.md).
This guide uses that same schema-4 case, C1 CPU/OpenMolcas backend, selected-root CAS/CASPT2 and factorized RICD/CD integrals.
Install the CPU release first using the [installation walkthrough](NOCI_Installation_Walkthrough.md).

## Copy the case

```bash
NOCI_INSTALL="$HOME/bin/NOCI.jl/v26.10.0"
source "$NOCI_INSTALL/bin/noci-environment.sh"
noci-prepare init "$HOME/noci_cases/ethene"
cd "$HOME/noci_cases/ethene"
noci-prepare check 00_system_define/ethene_dimer.yaml
noci-prepare plan 00_system_define/ethene_dimer.yaml
```

Edit the user-owned YAML, XYZ, seeds and templates before checking.
Review monomer geometry/basis/AO order and selected roots; the program does not select or assess active spaces.
Normal check/plan validate backend identity without launching a calculation.
For schema review without backend/files, use `--structure-only`; that does not certify the reserved PySCF route.

## Execute the stages

The following command launches real calculations:

```bash
bash run_all.sh ethene_dimer.yaml
```

For scheduled work, select one stage at a time with `prepare`, submit its outstanding tasks from `tasks_to_submit.txt`, and then use `finalize` on actual completed results.
Use `compute` for direct workstation execution, or `all` for the complete current stage.
Stage 05 is a Julia job; rotation, CommonOrb and integral transformations in finalize also perform numerical work.

| Stage | Required result |
| --- | --- |
| 01 states | Original monomer RasOrb/VecDet, selected-root energies, completion and backend records. |
| 02 placement | Consistently positioned XYZ and instance-specific rotated orbitals. |
| 03 commonorb | Actual COMMONORB, short `.vec/.det`, frozen/deleted counts. |
| 04 integrals | `integrals.one`, `integrals.sys`, `factors.jld2` in the actual common basis. |
| 05 run | Generated AHPC/factorized YAML, progress, `.out`, final `.json`, snapshot and optional checkpoint. |

Only intrinsic stage-01 tasks are shared between projects; every aggregate basis/integral/result is project-specific.
RICD atomic auxiliary-basis thresholds and molecular-CD thresholds have different meanings.
CASPT2 is enabled by default and can be disabled explicitly; disabling it gives zero fragment correlation correction without changing the CAS wavefunction.
No conventional four-index `.two` is generated by this standard workflow.

## Continue or change a calculation

Reuse requires matching scientific definitions, seeds, templates and backend identity, plus real valid products.
Changed aggregate inputs use a new project; changed same-name intrinsic tasks require a new carrier or independent case root, not merely a new project.
Use valid production checkpoints to continue incomplete NOCI; do not replace final JSON with a changed calculation.
Inspect locks and their owning processes before removing a stale lock.
Queue/account/node-scratch settings remain deployment configuration and are not embedded in the example.
See the [detailed tutorial](../../examples/ahpc_noci_standard/TUTORIAL.md) for frozen-core assumptions, root selection, MEBF/spin definitions and troubleshooting.
